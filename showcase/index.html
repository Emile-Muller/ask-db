What it does

/question

Ask anything about the shop's data

Type a question like “Which 10 product categories make the most revenue?”. You get the SQL, the answer and a full record of every safety check it passed or failed.

/question-review

A second opinion on every answer

A separate AI, with no access to the database, reads the record and judges whether the answer is actually right, or whether a refusal was justified.

Dataset
Olist Brazilian E-Commerce: about 100k real, anonymized online orders (2016–2018) with customers, sellers, products, payments and reviews.

Five safety layers

The AI never decides what runs. Each question passes through five checkpoints; the first one that says no stops it. The numbers show where the blocked test inputs were stopped.

  1. ? You ask a question, or paste SQL
  2. 1 Input screen Catches tricks like “ignore your instructions” and oversized input.
  3. 2 AI proposal The AI sees only safe tables and suggests one query, or declines.
  4. Security boundary: holds even if the AI is fooled
    1. 3 SQL validator sqlglot reads the query: one read-only statement, approved tables and functions, a row limit.
    2. 4 Locked-down run Read-only database, no files or network, 5-second timeout, 100 rows max.
  5. 5 Output check Removes restricted columns and masks emails or phone numbers.
  6. ✓ Answer + record then an independent review

How to read the “Reviewer agrees?” column
  • A second AI, with no database access, checks each outcome. The column says whether it backs what the system did: answering, or blocking.
  • ✓ Agrees: the answer is right, the refusal was justified, or the pasted SQL was bad so blocking it was right. ✗ Disagrees: the reviewer thinks the system got it wrong.
  • – No verdict: the reviewer couldn't judge it, usually because the input was stopped before there was a query or a result to check. Expand a row to see the reviewer's raw verdict and reasoning.
  • The safety layers decide whether a query is safe; the reviewer checks whether an answer is correct.
